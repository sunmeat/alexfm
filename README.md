# 🎙️ Alex FM

> Онлайн-радио с единым эфиром, karaoke-текстами и живыми визуализациями на весь экран.

**Alex FM** — веб-плеер интернет-радио, в котором все слушатели находятся в одном общем эфире.  
Без индивидуальной перемотки и личного таймлайна — только синхронизированное с сервером воспроизведение.

На фоне работает кинематографический visualizer на **Canvas 2D**, а под плеером отображаются тексты песен с подсветкой текущей строки.

## 📡 Синхронизация эфира

Клиент периодически запрашивает:

```http
GET /api/now-playing
```

Сервер сообщает информацию о текущем треке и его позиции:

```json
{
  "file": "track.mp3",
  "artist": "Artist",
  "title": "Title",
  "offset": 42.5,
  "serverTime": 1693000000.123,
  "nextTrackIn": 180
}
```

После получения данных клиент:

1. учитывает сетевую задержку;
2. вычисляет актуальную позицию в треке;
3. запускает воспроизведение с нужного offset;
4. отслеживает дрейф синхронизации;
5. мягко корректирует позицию при отклонении более чем на 2 секунды;
6. блокирует ручной seek.

Таким образом, несколько пользователей, подключённых в разное время, остаются в **одном эфире**.

---

## 🔊 Воспроизведение

После нажатия **▶ Слушать**:

- создаётся `AudioContext`;
- аудио подключается к `AnalyserNode`;
- плеер получает позицию из серверного состояния;
- запускается поток воспроизведения;
- visualizer начинает получать данные частотного и временного анализа.

`AudioContext` создаётся только после пользовательского взаимодействия, что соответствует ограничениям браузеров на autoplay.

## 🎤 Lyrics

Для получения текста используется:

```http
GET /api/lyrics?artist=...&title=...
```

Пример ответа:

```json
{
  "found": true,
  "synced": "[00:12.00] Первая строка\n[00:18.50] Вторая строка",
  "plain": "Первая строка\nВторая строка"
}
```

### Если доступен LRC

Клиент:

- парсит таймкоды;
- определяет текущую строку;
- подсвечивает её;
- автоматически прокручивает список.

### Если синхронизации нет

Используется обычный текст песни без karaoke-подсветки.

Если текст отсутствует полностью, lyrics-блок не отображается.

## 🔌 API

| Метод | Endpoint | Назначение |
|---|---|---|
| `GET` | `/api/now-playing` | Текущий трек и состояние эфира |
| `GET` | `/api/lyrics?artist=...&title=...` | Получение текста песни |
| `GET` | `/tracks/<filename>` | Аудиофайл текущего трека |

### `/api/now-playing`

Возвращает:

| Поле | Описание |
|---|---|
| `file` | Имя аудиофайла |
| `artist` | Исполнитель |
| `title` | Название трека |
| `offset` | Текущая позиция в треке |
| `serverTime` | Время сервера |
| `nextTrackIn` | Время до следующего трека |

| Действие | Результат |

### Только frontend

Запусти статический сервер из директории проекта:



## 🧠 Почему Vanilla JavaScript?

Для этого проекта использование React или Vue не даёт существенных преимуществ.

Vanilla JS позволяет напрямую работать с:

- Web Audio API;
- `AnalyserNode`;
- Canvas 2D;
- HTML5 Audio;
- браузерными событиями;
- таймингом синхронизации.

Это уменьшает runtime-overhead и оставляет полный контроль над аудио и графикой.

## 🔒 Технические особенности

- Пользовательский seek отключён.
- Позиция воспроизведения периодически сверяется с сервером.
- Дрейф более 2 секунд корректируется автоматически.
- `AudioContext` запускается после пользовательского жеста.
- Visualizer получает данные непосредственно из Web Audio API.
- Lyrics работают как с синхронизированным LRC, так и с обычным текстом.
- При отсутствии текста lyrics-интерфейс скрывается.

## 🤝 Добавление нового visualizer

Чтобы добавить новый режим:

1. Создай функцию `drawSomething(w, h)` в `visualizers.js`.
2. Добавь название режима в `modeNames`.
3. Добавь функцию в массив `drawers`.

Например:

```javascript
function drawSomething(w, h) {
    // drawing logic
}
```

После добавления функция автоматически становится частью системы переключения режимов.
